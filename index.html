Featured Deep Dive: Async HTTP Retry Engine

The Problem

When integrating with third-party APIs, network timeouts and temporary server errors are inevitable. Immediately retrying a failed request often fails again or overwhelms the target server. I needed a system that could intelligently delay and retry requests in the background without blocking the main application flow.

Architecture & Request Flow

The service is built on FastAPI using Python's AsyncIO. When a request fails, it isn't dropped; it is logged to an SQLite database with a "pending" state. A background worker continuously polls this database. Instead of a fixed delay, the worker calculates the next retry time using exponential backoff (delays get progressively longer) combined with randomized jitter (adding a random time variance to prevent multiple failed requests from synchronizing and hitting the target API at the exact same millisecond).

Technical Challenge & Solution

Challenge: Implementing the jitter logic asynchronously without blocking the event loop or causing race conditions in the database state updates.
Solution: I isolated the delay calculation into a pure, testable mathematical function. For execution, I utilized `asyncio.sleep()` for the jitter delay, ensuring the worker thread remained non-blocking and could handle other incoming requests concurrently while waiting to execute the retry.
